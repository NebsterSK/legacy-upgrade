You would not copy the same helper function into multiple projects. So I stopped copying the same coding rules into multiple project files.

My instructions for Claude live in two places now.

🏠 One CLAUDE.md in my home directory, for how I want code written no matter what I am working on. What good code looks like to me, what I never want to see. That file follows me into every project.

📦 One CLAUDE.md per project, for what is only true here. "This site exports to static HTML, so there is no server code and nothing that runs on request." Useful in this repo, meaningless in the next one.

The way I decide is one question. Would this still be true on my next project? If yes, it goes in the home directory. If it is about this stack or this repo, it stays local.

It sounds like housekeeping, but it is the same reason we extract a function. Duplicated rules drift. You fix a rule in one project, forget the others, and now your files quietly disagree about how you want to work. The model does whatever the nearest file tells it, and you are left wondering why the output changed.

DRY is not only for code. It applies to anything you write down and expect to reuse.
